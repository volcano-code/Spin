## 2. 原生编码导出：减少重复编码，保留完整性检查

新增 `NativeSourceSpinMaterialResult.iter_diagnostics_json()` 与
`write_encoded_archive()`。大型迭代 payload 直接在原生层生成 JSON 字节，避免旧路径
先生成 C++ JSON、解析为 Python 对象、再重新编码大型数组的来回转换。

仍逐条严格解析、检查顺序、重复 JSON 键、有限数、行长度、完成 footer、摘要与 EOF。
没有通过省略轨迹、抽样记录或绕过 readback 获取性能。字典 API 保持兼容。
额外标量字段保持 float 表示和 signed zero；两个编码器的归档字节/hash 可不同，
科学记录使用规范 JSON 比较，不使用会混淆 int/float 或 signed zero 的简单数值相等。

`online_compare.py run` 新增显式 `--trace-encoding native-json`，记录进 provenance 和
summary；默认仍为 `dictionary`，不静默改变既有实验。

三个小型真实原生回归（正常、资源拒绝、阶段上限）分别包含 42、1、40 条事件。
冻结旧 binding、当前字典导出和当前 native-json 的全部科学字段摘要一致。
另外覆盖 disk spool、owner 生命周期、原生记录损坏和归档伪造。

这些小测试只证明等价和接口正确；**未测完整 G7 导出提速或整作业是否不再超时**。
本轮为可审计增量 binding 构建，复用冻结核心及 pybind 主对象，记录 compiler、
链接输入、实际 header dependencies 和模块摘要，不冒充全量重编译。
最初诊断构建缺少 CMakeCache，扩展材料 runner 回归确实被证据门拒绝（9 passed /
1 failed，保留 `bridge-regression.log`）。随后在当前目录真实执行 CMake 配置，
没有复制缓存或削弱 `NATIVE_BUILD_CACHE_REQUIRED`。编译仍是上述明确记录的增量
构建，不把“配置完成”写成“全项目重编译”。完整 G7 CLI 流程尚未重跑。

## 3. 失败终态的真实归档审计

原求解器在 relaxation 未收敛时不会执行 split/merge，旧检查器却要求成功转换的
哈希链，从而将真实 UNKNOWN 归档拒绝为 `TRANSITION_HASH_MISMATCH`。

新增严格的未执行分支：前后分区、哈希和 fill 必须完全相同；split/merge 的哈希、
变化列表和未执行矩占位符必须为空/零；`paper_resolution_complete` 必须为 false。
不会把空哈希补成成功链，也不会因为终态有 KKT 记录就当作收敛。

对旧 repeat-1 的 1.2 GB 完整归档重新检查全部 1007 个事件后，12 个阶段可完整审计。
最后阶段仍为 `NUMERICAL_UNKNOWN`，转换为 `NOT_EXECUTED_SOLVER_NOT_CONVERGED`，
binary comparison unavailable，geometry unavailable。repeat-0 缺 footer 的归档没有升级。

该修复针对已有完整终态记录的 relaxation 失败；不声称解决缺失 trace、初始求值拒绝
或其它尚无协议的终态。旧审计结果保留；以 `failed-stage-audit-current.json` 的当前
检查器摘要为准。新源码不反向绑定旧实验为“由新源码运行”。
