# Spin-It 2014：断点恢复基础接口与跨进程验证

## 本轮完成了什么

已实现 `SourceAdaptiveDomain::restorePartition`，并验证恢复后的分区可以在新进程
中执行下一阶段真实 SLQP，得到与不中断路径逐字节相同的结果和完整迭代内容。
这是已批准阶段边界恢复方案的底层组件，**不是完整实验 checkpoint/resume 功能**。

项目：`/data/xvxinyao/moment-guided-spin-v1/code/make-it-balance-paper-sim`。
证据目录：`build/spin2014-partition-restore-20260916`。
仍在 `spin-it-strict-computational-v2` 独立工作树；没有覆盖主项目、创建提交或标签。

## 恢复接口的保证

- 仅接受源几何、原层级/叶数量限制、严格排序的叶坐标和预期分区摘要；不读取
  快照提供的质量矩。每个单元的十项矩从不可变源几何重新查询。
- 先检查数量、层级和坐标范围，再分配、查询或执行整数位移。
- 拒绝无序、重复、缺失、重叠、空贡献叶、根范围外坐标及错误源/设置身份。
  不自动排序输入，避免把已有 beta 分配给错误叶单元。
- 重建覆盖关系、邻接图、Laplacian 和分区摘要。
- 真正为空的保守设计域可还原为空；不将其解释为可行优化结果。
- 原有从源几何初始化的构造行为及摘要保持不变。

摘要是完整性检查，不是来源认证。该接口没有保存或验证 beta/phi、整个求解器
请求、模块身份、历史阶段或累计墙钟；这些属于后续上层断点协议。

## 实际验证

1. **红→绿**：先编译、运行测试对旧接口进行检测，得到
   `partition restoration API missing`（退出 1）；新增实现后通过。
2. **几何与转移**：独立解析立方体矩、原分区、混合层级分区、继续细分/合并、
   递归合并到初始层级以下，均保持全部单元矩、图、Laplacian 和摘要一致。
3. **反向检查**：构造“哈希仍匹配”的缺块、重叠、超预算和空叶输入，拒绝不能
   仅靠身份不匹配触发。错误源、层级、预算和非法坐标同样拒绝。
4. **实际故障注入**：只在 build 副本移除叶数量限制或覆盖验证，测试分别因
   `restore leaf budget ignored` / `invalid restored partition accepted` 失败（退出 1）。
   生产文件始终保留保护；故障副本不参与正式构建。
5. **跨进程真实下一阶段**：测试先完成一次非平凡 SLQP 和 split/merge，写出
   测试状态；两次分别启动新的原生进程、重新构造源几何和分区，再运行下一阶段
   SLQP。该阶段也确实执行迭代并收敛；输入 beta、结果、质量矩及每条二进制
   编码迭代记录与不中断路径逐字节一致。截断的测试文件被拒绝。
6. **回归**：最终选择的 7 项原生 CTest 全部实际通过；34 项 Python 回归通过，
   无跳过。源几何 level-9 回归是单元测试，不是论文 level-9 优化案例完成。
7. **UBSan**：固定仓库 Eigen，新增分区恢复及验证路径无未定义行为报告；链接的
   其他冻结几何组件不因此被宣称全部重新插桩。
8. **只读复核**：无生产缺陷发现；两处测试遮蔽问题已修正并用实际故障注入验证。

跨进程两次科学输出 SHA-256 均为：

跨进程输入是解析的 `SYNTHETIC_REGRESSION`，不是作者模型。测试文件明确标记

fsync、来源绑定、历史阶段或累计预算机制。

## 旧茶壶流程兼容性

另用新模块对原 G6O6 配置完整运行两次。继续使用 24 GiB、300 秒、单线程、
12 阶段、每阶段 960 迭代、12000 叶单元和原 1e-6 二值门槛，没有改参数。
两次运行的当前 provenance 校验、完整归档比较和独立方向重放均通过。
每次 120 个接受步，最大状态重放误差 0，最大 QP KKT 重放误差约 4.01e-15。

完整科学归档仍与冻结历史记录相同：

`7d0be4df50615f7ff7ebcee1ff2ca4a417414e868201bbb015fee2ad061ae956`

二值残差仍是 **4.647020231279599e-6 > 1e-6**，因此仍为
`BINARY_VALIDATION_FAILED`。这两次是不中断兼容性测试，不是茶壶断点续跑实验。
旧结果的当前源码绑定自动成为 `STALE_RESULT`；历史归档比较不改写或升级旧绑定。
本轮没有再次运行此前超时的 G7O7，也没有新增几何封存或仿真视频。

## 接下来仍必须实现

2. 对 beta/phi、历史完整阶段和 trace、源码/配置/模块/依赖身份建立可核验绑定。
3. 原子持久化发布断点，保留上一有效版本；新进程恢复完整历史并继续阶段计数。
4. 累计所有尝试的资源预算，不因重启而重置；未完成的当前阶段需要重算。
5. 对各阶段实际中断/恢复、篡改、错模块、遗漏阶段和预算重置执行完整实验级反向测试。

只有以上接通并通过全轨迹比较，才能宣称“完整阶段边界续跑可用”。当前仅底层
分区恢复及单个阶段的跨进程等价性通过；两篇论文完整计算复现仍未完成。
