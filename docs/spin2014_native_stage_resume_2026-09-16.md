# Spin-It 2014：native 完整阶段历史暂停与继续

## 本轮范围

在独立工作树 `/data/xvxinyao/moment-guided-spin-v1/code/make-it-balance-paper-sim`
接通 `solveSourceAdaptiveSpinStages`：真实源自适应优化完成 SLQP 和原子的
split/merge 后可暂停；继续时携带全部已完成阶段，而不是从第零阶段重跑。

**当前接口是同一进程内的可信状态令牌，不是生产跨进程断点恢复。**
上一轮磁盘存储载体和本轮 native 状态仍需通过生产编码/解码协议接通。
没有放宽算法容差、增加全局阶段预算、修改论文终止规则或升级论文完成状态。

## 实现与保证

- `SourceAdaptiveCheckpoint` 只能由求解器生成，外部不能通过手填 beta/status
  构造它。保存分区、beta、phi、完整阶段元数据、历史迭代及成功阶段累计轨迹字节。
- 返回给调用者的可变诊断结果与令牌内的历史是不同副本；修改诊断结果不会改变续跑状态。
- `maximumNewPasses` 只控制本次调用的执行分段；原始 `maximumAdaptivePasses`
  仍绑定于请求摘要，不能在继续时增加或从零重新计数。
- 继续前检查请求、存储模式、声明字节预算，以及全部历史迭代的完整二进制摘要。
  由源几何重新构建分区及质量矩；使用保存的 beta/phi 从全局下一阶段开始。
- 磁盘轨迹保持流式，不展开为完整驻留轨迹；要求历史文件不可变。继续使用新的
  排他尝试目录，保留并引用旧目录，检查失败发生在新目录创建之前。
- 只有成功完成求解和自适应转移、且确实还有未完成阶段时才产生令牌。
  真正完成优先于暂停；非收敛、细分资源失败或全局阶段耗尽不能生成可续跑令牌。
- 暂停状态为 `STAGE_BOUNDARY_PAUSED_NOT_VALIDATED`，不具有二值材料验收结果。

## 验证

测试先在缺少接口时失败，记录 `RED: native complete-history stage continuation is unavailable`。
实现后对同一个连续优化任务，在每个可暂停边界执行一次暂停/继续，并与不中断结果比较：

| 合成回归 | 终止规则 | 总阶段数 | 可暂停边界 |
|---|---|---:|---:|
| 非对称静态体 | UnchangedPartitionKktV1 | 4 | 3 |
| 非对称静态体 | PaperPostTransitionV1 | 3 | 2 |
| 非零 phi 的旋转体 | UnchangedPartitionKktV1 | 2 | 1 |
| 非零 phi 的旋转体 | PaperPostTransitionV1 | 1 | 0，必须直接完成 |

四组最终状态、科学摘要、beta/phi、完整历史阶段和逐条迭代字节均相同。
继续路径另行构造相同源几何，避免只依靠原域对象的驻留缓存。
磁盘模式也完成多阶段续跑，并从同一个令牌建立两条相同结果的分支。

反向检查包括：修改请求/总阶段预算/字节预算、切换内存与磁盘模式、零执行额度、
非收敛与资源失败、阶段耗尽、损坏旧 trace，以及重算记录 SHA-256 和完成尾标后的篡改。
最后一种修改的是历史科学摘要未覆盖的 `activeVariables` 字段，仍被新完整记录摘要拒绝。
实际故障副本移除该检查后，测试以 `rehashed full-record tamper accepted` 退出 1；
生产源文件未移除保护。

字节预算测试设置“第一阶段已用字节 + 48”，继续时第二阶段文件不得超过剩余 48 字节，
并必须因预算不足失败，不能把原预算当作新的可用额度。

49 项 Python 存储回归通过；原 source-adaptive 回归通过，其 stdout 与本轮另行运行的
上一轮冻结程序完全一致。这不是重新验证全部 Python/native 测试或完整论文算法。
自动验证脚本独立保存每个子进程退出码及 stdout 摘要，不提供手填通过开关。

## 修正与复核

初次实现把基础 `hashAuditedSlqp` 与 Givens 包装层额外绑定最终状态的摘要直接比较，
因此合法恢复也被拒绝。追踪原实现后改为私有的完整迭代字节摘要；不改变原科学摘要。
旋转体在论文终止规则下实际只需要一个阶段，因此测试明确要求直接完成，无人为断点。
独立只读审查未发现重要实现问题；按建议补齐双向存储模式切换拒绝测试。

## 还不能声明的能力

1. 令牌不能写入磁盘并在新进程解码；没有 Python 完整续跑入口。
2. 没有整合 `StageCheckpointStore` 的生产状态格式、版本迁移和不可信历史语义校验。
3. 本接口仅保留成功阶段轨迹计数；未累计失败尝试、重复分支、全部磁盘占用或真实墙钟。
   这些必须由上层监督器计量和强制执行，当前不能用于规避实验资源上限。
4. 尚未做完整实验的多进程杀死/恢复对照；未重跑 G7，未产生新的论文模型成功结果或视频。

下一步是生产状态编码/解码、封存历史 trace 的只读重载及跨进程监督器；必须先通过完整
中断/恢复等价性和累计资源反向测试，才让原长实验使用续跑。
