# Spin-It 2014：原生轨迹哈希内存与真实细分复查

本轮不改变目标函数、SLQP 数值流程、舍入规则或验收阈值。整体状态仍为
`PARTIAL_BLOCKED`；茶壶为 `RECONSTRUCTED`，不计入作者原始案例完成数。

## 原生哈希修复

`hashAuditedSlqp` 原先把完整历史格式化到字符串，再调用内容哈希。新增
`verification::Sha256Stream` 以固定 8192 字节缓冲区接收同一 ostream 序列，
复用既有 SHA-256。字段、次序、classic locale 和 hexfloat 均不变。
digest 是快照：可重复读取，也可继续写入；错误流和重定向缓冲区被拒绝。

保留 640 万个 double 的合成轨迹先在旧实现上复现内存问题：峰值
448928 KiB，192 MiB 地址空间限制下失败。新构建的限额回归实际通过，
峰值 56164 KiB，且 SHA-256 与旧实现相同。该测试不是论文案例。

SHA 流测试覆盖已知向量、块边界、嵌入 NUL、格式化和错误流。独立审查指出的
C++17 target 要求和 CTest 未强制内存上限问题均已修正；Linux 注册了实际
setrlimit 的限额测试。7 项相关 CTest 与 72 项 Python 专项测试通过，无跳过；
两组存在覆盖重叠，不能相加，也不代表全项目测试通过。pytest 有既有 asyncio
配置弃用警告，未影响执行。

**仅哈希的额外缓冲区有固定上限，原生求解器仍保存完整历史。** 此改动不构成
有界内存的完整 level-9 实现。

## G7/O7、960 次预算

预先声明的计划与配置保存在结果目录。相对既有 G7/O7 配置，仅 SLQP 预算
240→960，另外追加来源元数据；已用逐字段比较验证。原表面重新建立深度7
源树，不是上采样。叶节点和 cuboid 上限仍为12000，自适应轮上限12，二值
阈值仍为1e-6。

两次运行均完成记录和读回校验：5轮、1342条迭代、1348个完整事件。状态均为
`RELAXATION_UNKNOWN`，诊断为 SLQP 达到迭代上限；没有进入二值结果验收。
完整档案 SHA-256 均为
`f29c6ca50b1b80d9c190beed5d8b1fea887750fde7d3b3f26d821d266ae539fd`。
整流程峰值1584356 / 1585248 KiB（约1.51 GiB），耗时150.861 / 150.526秒。
未触及24 GiB或12000叶节点限制，没有删去失败尝试。

最后一轮有10012个实际优化叶节点，其中 level3/4/5/6/7 分别为
16/108/60/152/9676。前四轮松弛子问题达到各自 KKT 门，随后在第五轮的
level-7 分区耗尽960次迭代。这比旧240预算在较浅层停止推进了一层，
但不等于完成 level-7 收敛，更不是 level-9 复现。

## 定位到的下一障碍

完整流式读取后的诊断见 `g7-diagnostic-r2-compact.json`，生成器为
`diagnose_trace.py`。两次全部读取的诊断数值相同；第一遍的非精简诊断也保留。
第五轮的 KKT 只作为该轮求解状态解释，不升级为最终材料封存证据。

| 最后一轮迭代 | 目标值 | 最优性残差 |
|---|---:|---:|
| 0 | 1.1958227970 | 1.7801364e-2 |
| 400 | 1.1190412212 | 1.0855304e-4 |
| 800 | 1.1188701007 | 2.8901937e-5 |
| 960 | 1.1188646735 | 1.4938706e-5 |

终态等式残差3.2323371e-12，小于当前1e-8；最优性残差仍大于1e-7。
960次步骤被接受，25个 trial 因 merit 下降不足被拒绝；105次记录了活动集
变化，54次一阶回退，无可行性恢复尝试。这证明本次主要未达标项是最优性，
**不能仅据这些计数断言活动集/L-BFGS 有代码错误或问题不可行**。

下一重点是以该轨迹定位活动集变化、曲率历史清空及一阶回退对收敛的影响，
先建立小型回归再调整实现；保持目标、约束和舍入阈值不变。连续高层级求解
完成后，才有资格比较其二值误差及导出封存几何。
