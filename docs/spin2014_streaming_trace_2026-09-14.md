# Spin-It 2014：完整轨迹流式导出与回放

本轮实现并验证的是**求解后的导出/读取内存优化**，不是新的挖空算法。
整体复现仍为 `PARTIAL_BLOCKED`。茶壶仍是重建输入，仍未通过二值约束门，
没有新优化成功的几何封存或物理视频；Faster 的实现未修改。

## 根因与修改范围

先前绑定的 `diagnostics` 一次生成全部 pass/iteration 的 Python 对象；旧实验
随后用 `json.dumps` 生成整份字符串，哈希又整文件读取。原生求解器也持有完整
历史，原生轨迹哈希还会构造字符串。这些是不同内存来源，不能混为一谈。

新增 `NativeSourceSpinMaterialResult.iter_diagnostics()`：

- 先输出不含 pass 数组的完整终态/来源记录头及实际迭代数量；
- 再逐轮输出不含 trace 数组的完整 pass 信息；
- 最后逐条输出该轮全部迭代，包括状态、导数、乘子、活动集、回退和失败尝试。

新旧接口复用相同的逐字段转换函数，旧 `diagnostics` 保持兼容。
迭代器通过共享所有权保留原生结果，外部删除结果对象后仍可读取；返回的可写
Python 对象不会修改原生历史。没有改求解器、停止策略、舍入、权重或容差。

`source_trace_archive.py` 按 JSONL 顺序写入，使用分块 SHA-256；尾部包含完整性
标记、记录数及前文摘要。顺序读取验证缺失、重复、错序、损坏、非有限数、重复
JSON 键及尾随数据，默认单条记录上限 64 MiB。失败写入保留部分证据，不生成
合格尾部，不覆盖已有路径。校验器保存不可变的计数快照，不能通过修改已经返回
的记录头改变后续验证。

**必须完整耗尽读取器才能完成校验。** 已读前缀不是已验证档案。档案校验不证明
作者身份、几何合法、物理稳定或论文复现成功。

这只使额外导出/读取内存与最大单条记录有关；**原生求解器依然保留所有历史**，
没有实现迭代中的在线写出，尚不能称为完全有界内存的 level-9 求解器。

## 实际工程回放

预先记录的配置为上一轮 `inertia-g6-o6-i960.json`：源深度6、优化最大层6、
SLQP 960 次、原始输入初始化、同一显式 `PAPER_POST_TRANSITION_V1`。模型、
设计域、轴、壳厚、初值、权重和 `1e-6` 门槛全部不变。
两遍均重新求解，未读取旧解作为初值；顺序执行，每遍 24 GiB / 3600 秒。
计划、命令、源码/模块摘要及结果在 `build/spin2014-trace-stream-20260914`。

| 指标 | 旧整份 JSON 流程 | 新流式流程 run1 / run2 |
|---|---|---|
| 完整运行峰值 RSS | 约 9.17 GiB | 1.657 / 1.661 GiB |
| 新流程原生求解阶段峰值 | 旧流程未分段测量 | 1.657 / 1.661 GiB |
| 本轮完整运行时间 | 历史约 116–117 秒 | 约 135 / 137 秒 |
| 自适应轮数 / 迭代记录 | 10 / 2417 | 10 / 2417 |
| 二值约束残差 | `5.962606538739975e-6` | 完全相同 |
| 状态 | `BINARY_VALIDATION_FAILED` | 完全相同 |

整个新流程峰值降低约 82%，但不宣称运行更快。新流程增加了完整顺序读回校验，
协议与旧计时并不完全相同，也不是论文性能基准。JSONL 约 1.5 GiB，旧缩进 JSON
约 2.9 GiB；减少的是排版和内存复制，不是迭代、数值精度或失败记录。

每遍共有 2428 个数据事件（记录头1、pass10、iteration2417）；两份完整档案
SHA-256 均为 `9bc4fba64e040b29fd75a344ad30603e5d6fb29a1c4942998b3a47abf6da4782`。
轨迹摘要、终态摘要均与历史 i960-r1 相同。

另外，完整读取第一份档案在 **512 MiB 地址空间上限**下成功，峰值 RSS
82624 KiB，约 81 MiB；同一上限下整份历史 JSON 读取产生预期 `MemoryError`。
两种测试均保留日志，不把预期内存负例当作求解失败或不可行证据。

## 完整字段对照及证据范围

`compare_trace_replay.py` 将两份新档案的每个数据事件与历史完整 JSON 对照，
包含全部终态、分区、向量、导数及失败尝试，不仅比较求解器摘要。
这个一次性迁移检查器有意加载旧大 JSON，并在独立 24 GiB 限额进程中运行；
它不属于常规流式读取路径。
最终执行证据保存为 `legacy-comparison.json` 和 `legacy-comparison.log`。

新运行记录实际生效的设置，同时单列 reference 路径、摘要和原始设置；避免把
旧 reference 的默认停止政策误写成本次实际政策。配置与原生记录头逐项核对。
当前源码、实际加载模块、输入资产及输出档案重新核验摘要。

旧构建和旧结果未覆盖。由于本轮修改绑定及 CMake，旧结果相对当前源码应视为
历史记录，不重新宣称为当前有效运行。修改前文件保存在本轮 build 目录，且
与旧来源清单对应摘要一致；两遍新运行绑定新模块及源码。
