# 秩二材料记录共享存储与流式证据：架构设计

日期：2026-10-07。状态：**方向已批准；本书面设计待用户审阅，产品实施尚未开始。**

用户本轮“批准”对应 R194 中提出的共享不可变父记录方案。该批准允许形成此设计，不自动批准尚未形成的实施计划。本文件不修改 2026-10-05 已冻结的源曲面设计和实施计划，不修改历史失败记录，不创建提交、标签或替换共享运行库。当前隔离工作树有 842 个已修改／未跟踪路径，继续完整保留。

## 1. 目的、事实与成功边界

解决当前完整 owner 材料构造中已经测得的内存阻塞，使原有几何流程能够在原预算内继续执行。设计不是新的曲面算法，也不授予材料或论文完成状态。

事实来源为既有 R191、R193、R194 记录：

- 原始 R191-05 作业在 24 GiB、swap 0、60 分钟预算下于约 30 分 45 秒被 OOM 终止。该运行没有完整材料 PASS。
- 最后记录到 final lift 的 triangle 12624 结束；这不是最终厚度全部通过或最终对象构造成功的证据。触发 OOM 的具体分配点仍未确定。
- 原输入实测 Covered/初始 Interior/初始 Lifts 的记录分别约 1.274、1.380、1.381 GB。递归持有的完整字符串下界约 12.316 GB，尚不含临时副本、代数对象及其他堆内存。
- 全部 1911 次 repair 的 91,250 行、683,417,292 字节与旧实现同序逐字节一致；后续 final material 没有旧成功结果可作比较。

本设计的成功条件：保持原记录字节与科学摘要，消除五类记录之间的父正文复制，以及构造／哈希／大文件输出中的隐式整串展开。实际内存效果必须由原输入测量证明，不预先承诺最终全 owner 作业成功。

## 2. 范围与非目标

修改范围限定为以下五个私有材料记录族及其直接消费者：

| 记录族 | 保留的嵌入关系 |
|---|---|
| CoveredFiniteMesh | coverage、triangulation 的原正文 |
| InteriorMesh | 初始的 base；边细分后的原 parent；各构造节点 |
| MaterialLifts | 实际 mesh 原正文 |
| StrictMaterialMesh | initial lifts 和 final lifts 原正文 |
| AutomaticMaterialMesh | inventory 和 strict 原正文 |

直接关联文件：`src/spin/RankTwo{CoveredFiniteMesh,InteriorMesh,MaterialLifts,StrictMaterialMesh,AutomaticMaterialMesh}.cpp`、同名 `src/spin/detail/*.h`、完整材料测试导出入口以及注册测试／构建依赖。新增共享组件放在 `src/spin/detail/CanonicalRecord.h` 和 `src/spin/CanonicalRecord.cpp`，保持私有 C++ 边界，不引入 Python API 或外部库。

不重构更上游的 coverage、registry、arrangement 记录；借用它们已经拥有的不可变正文，而非再复制。上游自身已有的重复内容属于剩余成本，不能声称本轮全部消除。

不改变谓词、节点顺序、repair 数量、面索引、原始 owner 集合、分支选择、容差、根证明、厚度判定、输出语法或预算。不得用仅存哈希的父引用替代原正文，不修改 `NOT_GRANTED`，不放宽失败状态。没有新实体封存格式或公共完成声明。

## 3. 方案选择

采用**不可变共享片段 DAG＋流式遍历**。子记录嵌入父片段引用，但逻辑输出仍包含父记录的全部原字节。

未采用的替代方案：

- 只消除 `.str()` 和哈希临时副本：无法消除递归持有的父正文，不足以处理已测下界。
- 文件支撑／映射完整记录：可以降低部分 RSS，但引入文件生命周期、部分写入、外部文件身份与故障恢复；此批次不引入第二个可变证据权威。

共享不会消除输出的逻辑长度，也不会消除遍历全部字节所需的哈希时间与磁盘成本。原日志、记录和 failed evidence 均不删减。

## 4. 私有记录组件契约

### 4.1 不可变数据模型

`CanonicalRecord` 是轻量共享句柄，指向已封存的只读节点。节点保存按原顺序排列的片段、经检查的逻辑字节数，以及独立的惰性连续视图缓存。

片段只允许以下三类：

1. **拥有字节块**：组件拥有的不可变字符串；新增本地文本按不超过 64 KiB 的块生成，避免先形成 GB 级完整本地串。
2. **有所有者的旧正文叶**：指向既有不可变对象的 `canonicalRecord()` 字符串，并持有该对象的共享所有者。没有所有者的裸指针／`string_view` 不可准入。
3. **父记录引用**：持有已封存 `CanonicalRecord` 节点，保留父正文的原逻辑位置。

叶的所有者不能是正在构建的对象自身；父节点必须在引用前封存。构造器不接收可变回调，不允许节点自引用、前向引用或封存后的修改。这使记录依赖是有向无环图。

旧叶适配器复制旧对象的轻量句柄并持有其真实底层所有者，取得稳定正文引用；不能依赖调用者局部变量或输入 vector 的存活。尚未具有不可变所有权保证的类型必须拒绝借用，不能以无所有者视图迁就。

### 4.2 构造与格式

私有 `CanonicalRecordBuilder` 接收本地格式化文本、旧正文叶和父记录句柄，封存后返回记录。局部输出流使用 classic locale，并保持当前默认 flags、precision、填充和换行行为；不得把格式化重构误作文本规范化。

插入父记录之前必须排空本地缓冲，插入后继续原顺序；嵌入 BEGIN/END 标记仍是原文本，不由片段身份重写。一次构造失败不能发布部分记录、半个哈希或通过对象。

所有逻辑字节数求和使用检查加法；溢出显式失败。不得先构造完整 `ostringstream` 再切片，那仍具有原峰值问题。

### 4.3 遍历、输出、哈希

内部提供按顺序访问字节块的遍历器。遍历使用显式栈，避免深层记录依赖耗尽调用栈。为逻辑输出遍历时，**不得去重共享节点**：同一父记录在语法中出现两次就必须输出两次。

五类对象增加只读接口：

- `std::uint64_t canonicalByteCount() const`：返回完整逻辑正文长度，不包含证书族哈希前缀。
- `void writeCanonicalRecord(std::ostream&) const`：逐块输出原正文，检测目标流初始状态、写入失败和实际完成状态；保持异常流原有异常，不静默吞掉错误。
- 内部共享记录访问仅供可信构造代码使用，不让调用方拼接“已通过”对象。

流式哈希复用仓库 SHA-256，实现 `SHA256(原证书族前缀 || 全部原正文)`。不能哈希片段 ID、缓存地址或父摘要代替正文。正文哈希不包括计时、存储统计或对象地址。

输出函数不自行更改目标流 flags，也不把整体字节数一次转为 `streamsize`；每块限长写入。它不负责调用者文件的原子发布。完整作业仍必须检查 flush／文件状态后才能写 PASS 和完成回执。

### 4.4 保留旧连续接口

现有 `const std::string& canonicalRecord() const` 保持签名与原字节，内部显式请求惰性连续视图。该调用可能占用完整逻辑长度的内存，必须在接口注释中说明。

缓存由记录节点共享，使用异常安全的一次初始化：展开失败不留下半个字符串，后续允许重试；成功后只读且地址稳定，随最后一个拥有该节点的句柄销毁。并发只读调用不数据竞争，不能以允许线程安全为理由授予数值并行权限。

几何对象换代必须创建新的记录节点与新的缓存；不能从旧 `Impl` 复制一份已经展开的缓存并误作新正文。`insertRankTwoMovingEdgeNodes` 可以保留其几何复制语义，但新记录及哈希必须在发布前完全替换，旧父记录只能作为父引用。

五类已迁移记录的构造、`scientificHash()`、`canonicalByteCount()`、流式输出和内存测量均不能隐式调用其连续接口。借用未迁移旧叶时允许取得其已存在的连续正文，但不能复制正文；不能把已迁移父记录当成旧叶重新展开。保留小测试中的连续接口比较，不在原全 owner 路径中展开它。

## 5. 五类对象与导出集成

将 `Impl` 中的正文存储改为共享记录句柄；原几何、权威、设置和 hash 字段不改变。

- Covered 引用已有 coverage／triangulation 正文所有者；本地 covered-edge 行使用分块格式化。
- 初始 Interior 引用 Covered 的记录节点；细分 Interior 引用实际 parent 节点。各 NODE 的正文必须拥有构造节点句柄，不保留输入指针。
- Lifts 引用对应 mesh 节点，本地系数、点、约束及 triangle 行保持原生成顺序。
- Strict 引用 first／last lifts；即使两者恰好共享同一节点，原语法的两次正文也必须完整输出。
- Automatic 引用 inventory 原正文所有者及 strict 节点。

`tests/rank_two_complete_endpoint_import_regression.cpp` 中实际 `COMPLETE_OWNER_MATERIAL_BEGIN/END` 导出改为流式正文；保留原 envelope、flush 检查、科学哈希与成功标记顺序。其他未迁移族的导出不顺带重构。

所有源文件／构建调整需进入有效输入摘要和实际编译证明；历史 R191–R194 证据继续绑定旧源码，不能凭字节兼容改授当前版本通过。

### 5.1 已核查的额外消费者与测量边界

2026-10-07 的只读源码检查发现两项必须明确处理的边界：

- 历史 `r193-memory-wrapper.cpp::record()` 调用 `object.canonicalRecord().size()`。原有 eager-string 实现下这一测量有效；迁移后原样使用会展开惰性缓存。新的同范围探针必须对五类迁移对象使用 `canonicalByteCount()`，并记录展开状态；未迁移的 inventory 保留原计数。历史探针和回执不覆盖、不倒填。不能一边主动展开记录、一边将测量称为流式路径内存效果。
- `RankTwoFiniteCellTopology.cpp::certifyRankTwoFiniteCellTopology()` 在 `COVERED_MESH_BEGIN` 中消费 `mesh.canonicalRecord()` 并保存完整正文。现有产品源码搜索没有其他调用该函数的产品入口，调用位于独立 `rank_two_finite_cell_topology_regression.cpp`；原全量测试的 `verifyCoveredMesh()` 自身读取几何和摘要，不调用该检查器，也不展开 Covered 正文。因此该独立检查器本轮保留旧连续接口行为及其完整存储成本，用于小规模兼容验证；不得声称所有几何检查器都已流式化。将来若接入大规模公共载体，必须先处理此额外消费者，而不是隐式沿用本轮内存结论。

小型 covered/interior/lifts/strict/automatic、annulus 和 moving-edge 测试有显式连续正文导出／比较，继续验证兼容接口；不能将这些测试的峰值用作无展开流式路径的峰值。原全量入口和新的原输入探针才承担后者的范围验证。

## 6. 失败、度量与可信边界

格式、计数、输出或内存分配失败均是失败，不转换为几何不可行，也不继续发布材料对象。共享片段只能节约存储，不能跳过任何几何检查。

诊断附件区分：逻辑字节数、新拥有字节块大小、旧正文借用大小、缓存展开字节数和实测 RSS／cgroup peak。物理统计按实际存储节点去重，不与逻辑输出的重复次数混淆；共享所有者的内部几何堆成本不是已知字符串字节数。

诊断数据不进入科学摘要、不提供通过字段。验收要能证明父记录未展开；单看总 RSS 降低不充分。

## 7. 验证门与退出条件

先为以下行为建立实际失败测试，再实施：

1. 嵌套及重复父引用、空块、多个 BEGIN/END 的连续／流式／旧参考字节和族哈希一致；错前缀、漏块、换序和单字节变化被检出。
2. 临时父句柄、输入容器销毁后仍可读取；复制与移动对象保持身份，新几何版本不复用旧缓存。
3. 流初始失败、短写、抛异常、计数溢出不返回成功；展开异常不污染缓存。
4. 哈希、计数、流式导出不触发父展开；显式旧接口展开次数受控，重复及并发只读得到稳定正文。
5. 包含多层重复引用的记录，其逻辑大小可以大于实际拥有文本；遍历不能因物理去重漏输出。

验证按依赖推进：

- 组件契约测试；构建观察、链接和实际加载身份验证。
- 受影响 covered/interior/lifts/strict/automatic 以及 disk、annulus、moving-edge 原生回归。以已归档完整小产物比较所有正文／科学哈希，而非仅检查退出码。
- 原 owner-0 的同范围 footprint 探针，读取流式计数与哈希，禁止为测量调用连续接口。比较原 Covered/Interior/Lifts 字节数、摘要、所有原生几何指标，并测量 RSS、cgroup peak、未展开状态。
- 已保存 R194 全 repair 字节基线用于新运行的前缀比较。基线只覆盖该范围，不证明 final material。
- 正确性和测量门均通过后，才登记一次新的完整 owner 作业。维持原 24 GiB／swap 0／60 分钟、原 precision、owner 集合和谓词预算。不能因新存储效果不佳自动加预算重试。
- 如果完整作业成功，对每个实际 owner 运行独立 saved-material 检查和 shared seam 检查；若再次超限或几何失败，保存见证，结论仍为未完成。原 R192 检查器不能用于升级 OOM 产物。

本轮规格审阅不执行编译或原全量作业。后续实施计划应给出上述测试的真实入口、资源上限、证据目录和依赖，但不能提前写成测试通过。
