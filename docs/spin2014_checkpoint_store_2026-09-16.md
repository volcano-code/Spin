# Spin-It 2014：阶段状态持久化载体

本轮实现阶段边界恢复方案的第二个基础组件：`StageCheckpointStore`。
它保存不透明状态字节，并校验身份、文件完整性和阶段链；**不是完整实验续跑器**。
项目仍在 `/data/xvxinyao/moment-guided-spin-v1/code/make-it-balance-paper-sim`
独立工作树，没有整合或覆盖主工作区，没有提交或标签。

## 已实现

- 有界二进制帧、规范 JSON 元数据、SHA-256、严格 EOF、重复键拒绝。
- 源码/模块/输入/配置/检查器等调用者指定文件的路径、长度和内容摘要；
  每次操作重新检查。身份角色的完整性仍须由未来实验运行器保证。
- 外部历史文件摘要绑定；校验阶段连续性、父摘要和声明的累计计数。
- POSIX 本地私有目录内使用 `flock`、排他临时文件、完整写入循环、文件及目录
  `fsync`、不覆盖的硬链接发布。状态文件之后发布独立提交记录。
- 保留旧版本和 `.pending-*` 尝试文件；失败不删除旧证据。
- 任一已发布阶段损坏、缺失、错误身份或提交记录不匹配时拒绝读取，不静默回退。

## 中断行为与明确限制

| 中断位置 | 当前读取行为 |
|---|---|
| 新阶段链接前 | 临时文件保留，上一完整阶段可读 |
| 阶段链接后、提交记录前 | 孤立阶段被检测，报错停止；无自动修复 |
| 提交记录链接后 | 若完整文件对可见且校验通过，可读新阶段，即使调用者没收到确认 |

上述是**进程退出测试，不是断电测试**。协议使用同步操作，但未验证特定硬件掉电行为。
全链共同删除/回滚、主动攻击不在完整性协议的认证能力内。
目录必须为私有本地目录，外部身份及历史文件在操作期间不可变。

累计墙钟和轨迹字节仍是**调用者报告值**：存储器只验证单调性与声明上限，
不能计量被杀进程、执行截止时间或防止运行器漏计。集成夹具的墙钟为占位零值，
不作为资源测量证据。单帧大小有界，但所有历史及失败文件的总存储预算尚未实现。
外部 trace 摘要不证明其内容是完整合法的优化轨迹。

## 距离完整阶段续跑还差什么

1. native 成功阶段边界输出生产状态，完整保存 beta、phi、分区、请求和历史。
2. 状态解码的数学约束、完整历史/trace 语义校验，以及全部有效输入身份绑定。
3. 运行器恢复历史及阶段计数，处理中断留下的孤立发布，保证不重复计入接受阶段。
4. 实测并累计所有尝试资源，执行跨进程时间/磁盘预算，保留未完成尝试。
5. 全流程多边界中断恢复与不中断轨迹对照；之后才重跑较高分辨率实验。

本轮没有重跑 G7，没有改求解器数学语义或放宽验收容差，也没有新增封存几何或视频。
上一轮 G6 二值残差仍为历史的 `4.647020231279599e-6 > 1e-6`，不构成本轮新运行，
更不能改为论文复现通过。新增有效源码后，旧结果不能被称为当前源码的新鲜证据。
两篇论文的完整计算复现状态不因本轮存储测试通过而升级。
